# 🛰️ Satellite Image Sorter & Organizer

A comprehensive Data Structures and Algorithms (DSA) mini-project designed to catalog, sort, search, analyze, and organize satellite imagery using pure, from-scratch algorithmic implementations.

---

## 1. Abstract

The **Satellite Image Sorter & Organizer** is an interactive web-based software application built to demonstrate the practical utility of fundamental Data Structures & Algorithms on earth observation metadata. By eschewing high-level library abstractions (such as Python's built-in `sorted()` or database indexing routines), the system implements manual **Merge Sort**, **Quick Sort**, **Bubble Sort**, **Linear Search**, **Binary Search**, and custom **Separate Chaining Hash Tables** from first principles. Users can upload multi-format satellite imagery, extract acquisition dates and land classification metadata, run head-to-head algorithm benchmarks, visualize catalog statistics, and physically organize images into structured filesystem subdirectories.

---

## 2. Problem Statement

Satellite imagery datasets generated by remote sensing missions grow exponentially. Managing thousands of unorganized imagery files presents significant challenges:
- **Inefficient Retrieval**: Finding specific images by acquisition date, sensor resolution, format, or land type requires sequential manual inspection.
- **Lack of Structured Metadata**: Raw imagery files lack embedded catalog indexes, making filtering computationally expensive without dedicated data structures.
- **Educational Gap**: Standard application frameworks hide basic algorithm mechanics behind black-box API calls, obscuring algorithmic efficiency, time complexities, and memory trade-offs during computer science education.

---

## 3. Project Objectives

1. **Pure DSA Implementation**: Develop 100% manual, from-scratch implementations of Merge Sort, Quick Sort, Bubble Sort, Linear Search, Binary Search, and Separate Chaining Hash Tables without relying on built-in sorting libraries.
2. **Metadata Extraction & Cataloging**: Parse acquisition dates, timestamps, land classification types, dimensions, and file formats from standardized filename conventions (`YYYY-MM-DD_HH-MM_LandType.ext`).
3. **Interactive Visual Dashboard**: Provide a modern Streamlit interface featuring sidebar navigation across 8 core operational sections.
4. **Benchmarking & Performance Tracking**: Track comparison counters and execution timing (in milliseconds and microseconds) across sorting and searching operations.
5. **Data Export & Organization**: Enable automated metadata CSV generation and physical copy-based directory structuring by land type.

## 8. Data Structures Used

1. **`ImageRecord` Class**: Encapsulates single satellite image attributes: `image_id`, `image_name`, `date`, `time`, `datetime`, `land_type`, `image_format`, `width`, `height`, `file_size`, and `file_path`.
2. **Dynamic Array (`List[ImageRecord]`)**: Contiguous memory buffer holding catalog records, supporting $O(1)$ random access by index.
3. **Custom Hash Table (`ImageHashTable`)**: Manual hash table using **Separate Chaining** for collision resolution. Converts string `image_id` keys into bucket indices via a polynomial rolling hash function. Automatically rehashes and doubles capacity when load factor exceeds 0.75.

---

## 9. Algorithms Used

1. **Merge Sort**: Divide-and-conquer algorithm halving lists recursively around midpoint and merging sorted halves in $O(n)$ time. Guaranteed $O(n \log n)$ performance and stable element ordering.
2. **Quick Sort**: In-place divide-and-conquer algorithm utilizing Lomuto partitioning to place pivot elements in correct sorted position recursively.
3. **Bubble Sort**: Iterative comparison algorithm swapping out-of-order adjacent pairs across $n-1$ passes. Includes an early-exit optimization flag to halt in $O(n)$ time if input is already sorted.
4. **Linear Search**: Sequential scan checking element attributes one-by-one from index $0$ to $n-1$.
5. **Binary Search**: Logarithmic divide-and-conquer search halving search bounds around midpoint index `mid = (low + high) // 2` on pre-sorted arrays. Scans contiguous neighbors to collect duplicate key occurrences.
6. **Multi-Criteria Predicate Filtering**: Single-pass linear predicate evaluator checking land classification, image format, and date range bounds in $O(n)$ time.
7. **Polynomial Rolling Hash Function**: Computes hash codes using formula $\text{hash} = (\text{hash} \times 31 + \text{ord}(c)) \pmod{\text{capacity}}$.

## 10. Algorithmic Complexity Summaries

### Sorting Algorithms Complexity

| Algorithm | Best Time | Average Time | Worst Time | Space Complexity | Stability |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **Merge Sort** | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n)$ auxiliary | Stable |
| **Quick Sort** | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ | $O(\log n)$ stack | Unstable |
| **Bubble Sort** | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ auxiliary | Stable |

### Searching Algorithms Complexity

| Algorithm | Best Time | Average Time | Worst Time | Space Complexity | Prerequisite |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **Linear Search** | $O(1)$ | $O(n)$ | $O(n)$ | $O(1)$ auxiliary | None (Unsorted data) |
| **Binary Search** | $O(1)$ | $O(\log n)$ | $O(\log n)$ | $O(1)$ auxiliary | Sorted dataset by key |

### Hash Table Complexity (`ImageHashTable`)

| Operation | Average Case | Worst Case | Notes |
| :--- | :---: | :---: | :--- |
| **Insert** | $O(1)$ | $O(n)$ | Doubles capacity when load factor $> 0.75$ |
| **Search** | $O(1)$ | $O(n)$ | Chain lookup via Separate Chaining |
| **Delete** | $O(1)$ | $O(n)$ | Removals from linked bucket chains |
| **Space** | $O(n + m)$ | $O(n + m)$ | $n$ items across $m$ bucket slots |

## 15. Standardized Filename Convention

To enable automatic metadata extraction upon upload, filenames should follow the format:
```
YYYY-MM-DD_HH-MM_LandType.ext
```
**Examples**:
- `2026-01-15_14-30_Forest.jpg` $\rightarrow$ Date: `2026-01-15`, Time: `14:30`, Land Type: `Forest`, Format: `JPG`
- `2026-02-10_09-15_Water.png` $\rightarrow$ Date: `2026-02-10`, Time: `09:15`, Land Type: `Water`, Format: `PNG`
- `2026-03-01_18-00_Urban.webp` $\rightarrow$ Date: `2026-03-01`, Time: `18:00`, Land Type: `Urban`, Format: `WEBP`

*Note: Files not following this convention are still uploaded safely; missing attributes can be updated via the UI metadata editor.*

## 18. Limitations

1. **Session State Storage**: Catalog data resides in Streamlit's in-memory `st.session_state` and resets when the app process is terminated.
2. **Manual Land Classification**: Initial land classification relies on filename string extraction or user UI input (no ML vision classification).
3. **Single-User Desktop Flow**: Designed for local mini-project demonstration rather than multi-tenant cloud storage.
